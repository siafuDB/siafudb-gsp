# AGENTS.md — siafudb-gsp

Rules for AI agents and people working in this repository. They layer on the
org-wide guide, [nyuchi/.github AGENTS.md](https://github.com/nyuchi/.github/blob/main/AGENTS.md).
Where the two conflict, this file wins. Read `README.md` and the two specs in
`docs/` first.

## What this repo is

The Graph Sync Protocol (GSP) for [SiafuDB](https://siafudb.org), a Bundu
Foundation open project under Apache-2.0. It is engine-independent: the
SiafuDB adapter lives in [`siafuDB/siafudb`](https://github.com/siafuDB/siafudb).
The relay is untrusted by design. It sees ciphertext and opaque cursors only.

Every cryptographic part is draft and unaudited (`docs/WIRE-V0.md`,
`docs/SYNC-V0.md`). Do not describe any of it as audited or production-ready.

## Layout

| Path               | What                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| `crates/gsp-wire`  | Wire format: canonical CBOR ops, hybrid signatures, key log, sealing. |
| `crates/gsp-sync`  | The replica: pairing, payload, merge, outbox, cursor. No I/O.         |
| `crates/gsp-relay` | Reference relay: an HTTP server storing sealed items. Library + bin.  |
| `docs/WIRE-V0.md`  | Wire format spec. Test vectors are generated by `gsp-wire`'s tests.   |
| `docs/SYNC-V0.md`  | Sync spec: payload, merge rules, pairing, relay protocol.             |

`gsp-wire` is `no_std + alloc` and `gsp-sync` has no I/O, no clock and no RNG.
Keep it that way: both must build for `wasm32-unknown-unknown`.

## Build, lint, test

These are the commands CI runs (`.github/workflows/ci.yml`). Run them before
you push.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked

# Ed25519-only build that a browser bundle can use (the `ml-dsa` feature off)
cargo clippy -p gsp-wire -p gsp-sync --no-default-features --all-targets --locked -- -D warnings
cargo test -p gsp-wire -p gsp-sync --no-default-features --locked

# wasm32 (needs: rustup target add wasm32-unknown-unknown)
cargo check -p gsp-wire -p gsp-sync --target wasm32-unknown-unknown --locked
```

CI sets `RUSTFLAGS="-D warnings"`. The `ml-dsa` crate must stay absent from
`gsp-sync`'s dependency tree when the feature is off; CI checks this with
`cargo tree`. `Cargo.lock` is committed and every command uses `--locked`.

## Conventions

- **Rust only.** No other language in this repo.
- **Spec and code move together.** A wire or sync rule change updates
  `docs/WIRE-V0.md` or `docs/SYNC-V0.md` and the tests in the same PR. The
  wire test vectors are regenerated by `crates/gsp-wire/tests/vectors.rs`,
  which fails when the spec goes stale.
- **No `unsafe`** in the relay; its README states it has none.
- **Do not disable lints or tests quietly.** `#[allow(...)]` needs a same-line
  reason.
- **Conventional Commits** on every commit and PR title.
- **Pin third-party GitHub Actions to full commit SHAs**, with the version in a
  trailing comment, as `ci.yml` does.
- **No secrets in the repo.** The relay reads its tokens from the environment
  (`GSP_RELAY_REGISTRATION_TOKEN`); never commit a value.

## Out of bounds

- Do not weaken a cryptographic check, loosen verification, or make the relay
  see more than ciphertext and opaque cursors.
- Do not deploy or expose a relay, and do not touch DNS or infrastructure.
- Do not edit `LICENSE`.
